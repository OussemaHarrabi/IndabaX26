## 1. What this release is, in one paragraph

AegisGraph is a pre-execution decision gateway for agentic systems: given one
proposed agent action and the inert facts around it, it returns one of four verbs
— `allow`, `block`, `escalate`, `rewrite` — plus a reason, and never executes the
proposed action. This release changes **no measured result**: the scripted
campaign, the legacy ladders, the corrected load baseline and the container/SBOM
surface are the ones v0.1.0 published, and the numbers below name the same
artifacts. What it adds is (a) a documentation truth pass that removes claims the
repository had already outgrown, and (b) the **prepared, preregistered and not
executed** real-model campaign. **No real-model run exists in this repository**,
and none is claimed: the native real-model evidence class is empty by
construction, and the sealed holdout is still closed.

## 3. The three evidence classes, kept separate

The repository reports measured results in three classes and never merges them
([`evidence/qwen-campaign-freeze.md`](evidence/qwen-campaign-freeze.md) §0):

1. **Native benchmark, scripted replay** — the scenario's authored action script
   is replayed verbatim, so the run measures the gateway, not a model. Numbers:
   §4 (C1/C2 and the scripted ladder).
2. **Historical legacy SENTINEL evidence, real Qwen3-8B, frozen** — the preserved
   challenge-period package under an add-only policy; quoted, never recomputed.
   Numbers: §4 (the frozen legacy real-Qwen ladder).
3. **Native real-model campaign** — **empty**. This release adds the
   infrastructure that will fill it (§2.2) and the preregistration that fixes how
   it is judged; it adds no result.

A number from one class is never compared with a number from another, and no
table in this file mixes them.

## 5. What this release does not claim

- **No real-model result.** No native real-model run exists; the campaign is
  prepared, preregistered and not executed. Ledger row **P9** is `pending`, blocked
  on a GPU or cloud runtime, with the enabling action named in §6 and in
  [`research/qwen3-8b-campaign.md`](research/qwen3-8b-campaign.md).
- **No holdout result.** The sealed 20-scenario holdout stays closed; Stage D
  runs exactly once, after Stages B and C and the custodian's authorization
  ([`evidence/qwen-campaign-freeze.md`](evidence/qwen-campaign-freeze.md) §9).
- **No cluster behaviour.** No Kubernetes cluster smoke test has run (`kind` is
  not installed); the manifests are schema-validated and policy-asserted only
  (blocked row B1).
- **F9 is still open.** The suite is not executed inside the built image.
- **No significance claim the design cannot support.** The campaign's sample is a
  fixed case series, not a probability sample; the preregistered analysis reports
  counts before proportions, states the family size `m` beside every corrected
  p-value, and records an interval objective as *not evaluable* rather than passed
  when the discordant count is below its floor
  ([`evidence/qwen-campaign-freeze.md`](evidence/qwen-campaign-freeze.md) §6).
- **No universal protection, and no "proves".** The gateway bounds what one
  decision point can enforce on a fixed case series; it is not proof that any
  injection is detected.
- **No claim that the ablation switches have measured anything.** They define the
  configurations and are exercised by tests and by the live evidence in
  [`docs/benchmark/ablations.md`](benchmark/ablations.md) §4; no real-model ablation row
  has been produced.

## 6. How to reproduce

**Environment and commit.** The battery records its own environment block —
`recorded_at`, the commit and its short form, the branch, `dirty`, Python,
platform, `core.autocrlf`, the PostgreSQL URL it used, and the `docker`/`kubectl`
versions it found — into its transcript. This release's values are
`TBD-AT-RELEASE`.

```bash
# 0. The release verification battery (writes an auditable transcript under
#    docs/evidence/verification/<UTC>-battery.{json,txt}; a check that cannot run
#    is recorded "unavailable" with the reason, never as a pass)
python scripts/verify_release.py
python scripts/verify_release.py --skip-container
python scripts/verify_release.py --db-url postgresql+psycopg://user:pw@host:port/db

# 1. Tests, with and without PostgreSQL 17 (the db-marked tests skip cleanly without it)
python -m pytest -q
AEGISGRAPH_TEST_DATABASE_URL='postgresql+psycopg://user:pw@host:port/db' python -m pytest -q

# 2. Coverage gate (floor 95, above the no-database ratio on purpose)
python -m pytest -q --cov=aegisgraph --cov-report=term --cov-fail-under=95

# 3. Static checks and the dataset/reachability gate
python -m ruff check backend tests scripts benchmark
python -m mypy
python scripts/bench_validate.py

# 4. Provenance manifest (re-hashes every listed artifact, including the 60-file dataset aggregate)
python scripts/release_manifest.py --verify docs/evidence/release-manifest.json

# 5. SBOM drift guard, then the container build and the read-only smoke
python scripts/check_sbom_freshness.py
docker build --provenance=false --sbom=false -t aegisgraph:<tag> .
docker run --rm -d --name aegis-smoke --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=16m --cap-drop=ALL \
  --security-opt=no-new-privileges -e AEGISGRAPH_LEGACY_UNAUTHENTICATED=true \
  -p 18080:8080 aegisgraph:<tag>
curl -s http://127.0.0.1:18080/healthz

# 6. Schema migrations (URL from the environment, never from alembic.ini)
python -m alembic upgrade head          # docs/ops/migrations.md

# 7. Kubernetes manifests under both validators
python scripts/validate_k8s_manifests.py --validator both

# 8. The campaign: nothing runs without a runtime; see exactly what a command would do
python scripts/bench_campaign.py --stage B --seed 1729 --seed 42 --seed 7 --dry-run
```

The exact C1–C4 commands are in [`evidence/m6-freeze.md`](evidence/m6-freeze.md)
§3; the campaign's stage commands (A–D, resume, bundle) are in
[`research/qwen3-8b-campaign.md`](research/qwen3-8b-campaign.md) §15.2 and the
notebooks import them rather than reimplementing them.

**Enabling the blocked rows.** Real-model campaign: provision a GPU or cloud
runtime (the four notebooks), close the eight `TBD-BEFORE-STAGE-B` values at Stage
A, then `python scripts/bench_campaign.py --stage A|B|C ...`; the holdout needs
the custodian passphrase and the checklist in
[`docs/benchmark/holdout.md`](benchmark/holdout.md) §4. Cluster smoke test:
`kind create cluster --name aegisgraph && kubectl apply -k deploy/k8s`.

## 8. Known limitations

- **No real-model number** — the central limitation of this release (§5).
- **The eight `TBD-BEFORE-STAGE-B` values are still open** (model revision,
  quantization artifact digest, dtype, chat-template digest, max context tokens,
  the seed list beyond the anchor `1729`, the temperature > 0 sampling
  parameters, and the prompt/tool-schema digest). They are closed by recording
  the runtime's own reported values at Stage A; Stage B does not start with an
  open value.
- **Legacy mock scorecard not byte-reproducible.** The committed
  `evaluation/aegisgraph-mock.json` (`3233dfc5…`) is not reproduced from current
  code and has not been since M0 — one decision differs in
  `enterprise_memory_poison` step 9. The re-checks (`8669aadb…`) are the
  reproducible ones.
- **Single seed, no repeats** on the scripted campaign (seed `1729`) and one
  seeded run per legacy configuration; repeated-trial variance is not estimated.
- **Legacy utility gate unmet** (4/9 benign tasks, below the kit's 0.5 gate) and
  **residual output contamination** in one `enterprise_memory_poison` answer; nine
  of 31 legacy attacks were unreachable under allow-all and are not defence
  evidence.
- **Accepted residuals** (each with its reason in the ledger): dependency pins
  carry no hashes (F8); the legacy loopback refusal checks the configured bind
  variable rather than the actual bind (H3-06); the request body is buffered up to
  the 1 MiB cap before the credential is resolved (H3-08); `/metrics` is
  port-controlled rather than credential-controlled (P80); a caller-controlled
  span attribute is unbounded in distinct values (P84).
- **Manifest hash conventions are checkout-dependent.** `sha256_raw` is the bytes
  on disk in the generating checkout; `sha256_lf` and `sha256_blob` are the
  portable values, and every entry records which of them its blob matches.
