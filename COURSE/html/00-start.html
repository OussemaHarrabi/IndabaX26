Start here

This is a course about one project: AegisGraph, a defence gateway built for the SENTINEL agent-security challenge at IndabaX Tunisia 2026. It was written for someone who knows machine learning and agents, and knows nothing yet about security.

What you will be able to do by the end

  • Explain, in plain language, what a prompt-injection attack against a tool-using agent actually is — and why "tell the model to ignore instructions" is not a defence.
  • Read a SENTINEL scenario and predict which harm it is aiming at, which tool it targets, and how the evaluator decides whether it succeeded.
  • Trace a candidate action through the twelve gates of AegisGraph's decision kernel and name the reason code it will produce.
  • Judge a security claim the way a reviewer does: what was measured, what was only reasoned about, and what would falsify it.
  • Run the whole thing yourself and attack it — the labs give you the exact commands.

The project in one minute

A SENTINEL episode is a loop: a model proposes an action, a defence decides, a tool executes, and the result becomes the model's next input. The attacks never try to run code; they plant text — a line in a ticket comment, a vendor email, a log entry — and wait for the agent to act on it. The benchmark's own measurements say the reference model refuses to move money or disable monitoring, but happily looks up a record and copies a secret into an internal note. So the harm is a disclosure, not a dangerous-looking tool call.

AegisGraph answers one question for every proposed action: given where this text came from, what the user actually asked for, and where sensitive data is allowed to travel, may this action proceed? It answers with allow, block, escalate or rewrite — and it never executes anything itself.

What it achieved, measured and recomputed

With Qwen3-8B and no defence, 22 of the 31 published attacks reach their harm and succeed. With AegisGraph v5, 0 of those 22 succeed, while 4 of 9 benign tasks still complete, at a false-block rate of 0.86 % and 9.3 ms p95 latency. All ten scorecards, all fourteen SHA-256 digests and the 22-attack reached set were recomputed during this audit from the raw artifacts — they match. The run is a single seeded self-test on a published suite, not a jury score, and the kit's own gate marks it eligible=false because benign utility sits under 0.5.

They are teaching models

The decision simulator follows the same gate order as the real engine but is a simplification. Where a widget says "measured", a real request produced that answer; where it says "code reading", it was read out of the source.

One honest paragraph before you start

AegisGraph is a competent, well-evidenced instance of one specific idea: check every action against provenance, policy and the user's real goal before it executes. It is not a general solution to prompt injection, and its own documentation says so. What makes it worth studying is that it measures itself honestly enough for you to see exactly where it would break — paraphrased instructions, translated payloads, encoded payloads, longer multi-turn laundering, and any exfiltration channel that is not an external email recipient. Chapter 9 turns those into experiments you can run.

Check yourself

What does the defence actually control?
Only the decision about a proposed action: allow, block, escalate or rewrite. It never executes a tool, never talks to the model, and cannot change what the agent sees.
Why is the honest denominator 22 and not 31?
Because nine attacks never reach their harm even with no defence installed — the model refuses, or the tool it would need is outside the allowed set. Counting those as "stopped" would be dishonest.
What is the single largest category in the jury rubric?
Video and observability, at 40 of 100 points — more than the defence code itself. That is the category this project currently has not claimed.
Where do the numbers in this course come from?
From the repository's own artifacts: ten scorecards and their raw JSONL traces under evaluation/, recomputed during this audit. Mock-model numbers and real-Qwen numbers are always labelled separately.
